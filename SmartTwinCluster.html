⏱️ ZERO-TOUCH WORKFLOW

YAML 한 줄 → 346 노드 자동화

STEP 1 · 5 min

YAML 작성

nodes·partitions·SSO·SSL 등을 단일 YAML 에 선언적으로 기술. 호환 위치 다중 지원.

STEP 2 · 30 min

오프라인 패키지 준비

VM 자동 부팅 → APT·휠·소스 수집 → 1GB 분할 tar.gz 압축 → 사내 서버로 전송.

STEP 3 · 1 hr

전체 배포 (phase 0~10)

setup_cluster_full_multihead_offline.sh 한 줄. 10 phase 가 OS prep → DB → 인증 → Slurm → Web → GPU → 컴퓨트까지 자동.

STEP 4 · instant

점검·복구

check.sh / fix_slurm_state.sh / restart_slurm.sh — 단일 명령으로 진단·복구.

STEP 5 · zero

도메인 전환

public_url 한 줄 수정 → 인증서·nginx·프론트·SAML 모두 자동 갱신.

setup.sh
# 1. YAML 한 줄 수정 — 도메인 전환
public_url: "stcx.sec.samsung.net"

# 2. 전체 자동 셋업 (오프라인 + 멀티헤드)
$ sudo ./setup_cluster_full_multihead_offline.sh \
  --config my_multihead_cluster.yaml --yes

# 3. 또는 phase 단독 (slurm 만)
$ sudo ./cluster/setup/phase3_slurm.sh --config my.yaml

# 4. 단일 진단
$ ./check.sh my_multihead_cluster.yaml --verbose

📊 BEFORE vs AFTER

왜 AX 네이티브인가

🥱 전통 HPC 셋업

  • 설치 매뉴얼 200+ 페이지, 단계별 수동 실행
  • OS 버전·도메인 변경 시 30+ 파일 동시 수정
  • 에러 발생 → 운영자 stackoverflow 검색
  • 같은 사고 다른 운영자가 또 겪음 (지식 손실)
  • 인증서 갱신·키 sync 분기마다 수동
  • HA 구성은 별도 컨설팅

⚡ AX-Native (SmartTwin)

  • YAML 한 줄로 의도 선언, 나머지는 자동
  • 도메인·인증서·nginx·프론트 한 번에 자동 동기화
  • 에이전트가 로그 읽고 phase 스크립트에 영속 fix
  • 한 번 잡은 버그는 다음 운영자에게도 자동 적용
  • cert CN 자동 재발급 · munge key 자동 동기화
  • Keepalived VIP · GlusterFS 기본 내장
