# 레시피 등록소 계획 (2026-10-26)

## 왜
경험으로 정한 비교·분석 설정과 덱 수정 조합이 지금은 그때그때 사라진다. 기능을 하나 더하려면 KMM(Nuitka)을 다시 빌드하고 SIF·노드에 올려야 한다(빌드 약 1.5시간).
사용자 요청은 "함수 레시피를 써서, 효과가 있으면 LLM 이 등록" 이다. 운영 MCP 의 호출자는 서버팜 안에서 보안 감시를 받는 LLM 뿐이라 접근 통제는 위협 모델에서 뺀다(사용자 결정 10-26). 그래서 관문은 품질(효과를 본 실행과 같은가)에 둔다.

## 무엇을 — 1단계(이번)
- **레시피** = 기존 카탈로그 도구 하나(`kmm_chain`·`kmm_<모드>`·`post_*`)의 인자 틀 + 매개변수 정의 + 근거(효과를 본 잡) + 설명.
  - 코드가 아니라 데이터다. 실행은 원래 도구 경로(stmc_tools)가 그대로 한다 → KMM·후처리 바이너리 변경 0, 재빌드 0.
  - KMM 에 이미 있는 32 모드의 조합과 후처리 YAML(unified·custom·federate 등) 설정이 대상이다.
- **저장**: `/data/SmartTwinMCP/recipes/<이름>/<판>.yaml`. 판은 1, 2, 3… 로 늘고 덮어쓰지 않는다. 내용 해시(sha256)를 같이 적는다. 시험은 `STMC_RECIPES_DIR` 로 바꾼다.
- **도구 5개**(손으로 쓴 도구, `tools/recipe_*/1.0.0`)
  - `recipe_save` — 검증 + 근거 확인 + 새 판 저장(통과하면 바로 쓸 수 있음).
  - `recipe_list` — 이름·요약·태그·대상 도구로 찾기, 판·매개변수를 보여 준다.
  - `recipe_get` — 한 판의 전체.
  - `recipe_run` — 매개변수를 넣어 펼친 뒤 원래 도구로 제출(dry_run 가능). 응답에 레시피 이름·판·해시를 적는다.
  - `recipe_retire` — 판 내리기(만든 사람만, 이유를 남김). 파일은 지우지 않는다.
- **근거 확인(효과 관문)**: 근거 잡은 호출자 것이고, 끝났고 rc 0 이며, 레시피와 같은 도구여야 한다. 그리고 레시피를 근거 매개변수로 펼친 입력 글(`kmm`: `stmc_options.txt`, `post`: `stmc_config.yaml` 등)이 그 잡의 `work/` 파일과 같아야 한다 — "이 레시피가 바로 효과를 본 그 실행" 임을 보증한다.
- **매개변수**: 인자 틀 안 문자열의 `{{이름}}` 자리.
  - 값 전체가 자리 하나면 타입 그대로(숫자는 숫자), 아니면 글로 끼운다.
  - 타입(number·integer·string·boolean)·minimum·maximum·enum 을 검사한다. 선언 안 된 자리·쓰지 않는 매개변수는 거절한다.
  - 펼친 인자는 원래 도구의 args.schema.json 으로 다시 검사한다(보통 경로와 같다).
- **에이전트 지침**: AGENT_GUIDE 에 "새로 짜기 전에 recipe_list, 효과가 확인되면 recipe_save" 를 적는다.

## 1단계 밖(다음)
- KMM 명령줄 `*Recipe 이름,판` 펼치기 — KMM 빌드 한 번. 다음 KMM 판(요소 소실 시 비 0 종료·MAT_017 min(SIGY, FS)·KAM eval 교체)과 묶는다.
- 코드 레시피(새 지표 계산) — 후처리 Python 쪽 샌드박스. 실제로 필요한 사례가 나오면.
- 사용 결과 집계(효과 통계), 여러 근거·다른 덱으로 시험.

## 성공 기준
- pytest 새 시험 통과:
  - 저장과 판 증가
  - 검증 거절(선언 안 된 자리·쓰지 않는 매개변수·대상이 아닌 도구)
  - 근거 거절(남의 잡·rc≠0·다른 도구·입력 글 불일치)
  - 펼치기와 dry_run 실행
  - retire
- 기존 시험 전부 통과, lint 오류 0.
- 실제 확인: 이 서버의 기존 kmm_chain 잡(admin 의 stmc_kmm_chain_1174)을 근거로 저장한 레시피를 `recipe_run` dry_run 으로 펼치면 그 잡과 같은 `stmc_options.txt` 가 나온다.
